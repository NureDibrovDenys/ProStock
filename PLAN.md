# PLAN — ProStock: накладні (проведення), залишки, заповненість полиць

Спринт наступний за попереднім (авторизація / товари / довідники / накладні-чернетки).
Мета: замкнути цикл «накладна → проведення → залишки → заповненість → мапа складу».

## 1. Бекенд: облік залишків
- [ ] Модель `StockItem` (товар × полиця × пакування, кількість) + міграція Alembic
- [ ] Модель `StockMovement` (журнал рухів: прихід/вихід/коригування)
- [ ] CRUD залишків: підсумок по товару на складі, залишки за списком товарів
- [ ] `GET /api/v1/stock?product_ids=…` — залишки для форми вихідної накладної

## 2. Бекенд: розрахунок заповненості (об'єм, вага)
- [ ] Виправлення `Shelf.total_volume_m3` (габарити в метрах, а не в мм)
- [ ] Сервіс заповненості: об'єм/вага полиці та стелажа, відсотки заповнення
- [ ] Поля заповненості в `ShelfResponse` та `RackSummaryResponse`
- [ ] Заповненість стелажа у відповіді мапи складу

## 3. Бекенд: ієрархія стелаж → полиця
- [ ] Розрахунок заповненості сігментів: склад → стелаж → полиця → товар
- [ ] Розміщення товару при проведенні прихідної накладної (best-fit за об'ємом і вагою)
- [ ] Помилка «немає місця» з деталями по товарах

## 4. Бекенд: API вихідних накладних
- [ ] `POST/GET/PATCH/DELETE /api/v1/outbound-orders`
- [ ] Перевірка залишків при створенні/редагуванні (попередження) і при проведенні (блокування)
- [ ] Номер накладної присвоює бекенд

## 5. Бекенд: проведення накладних
- [ ] `POST /api/v1/inbound-orders/{id}/post` — приймання товару на полиці
- [ ] `POST /api/v1/outbound-orders/{id}/post` — списання залишків
- [ ] Структурована помилка нестачі (409): товар, потрібно, доступно, бракує
- [ ] Заборона повторного проведення та зміни проведеної накладної

## 6. Бекенд: список накладних
- [ ] `GET /api/v1/orders` — єдиний список з фільтрами за типом і статусом, пошуком, датами

## 7. Фронтенд
- [ ] Форма накладної: вибір постачальника / одержувача (довідник, лише активні)
- [ ] Сторінка списку накладнів: фільтри за типом і статусом, пошук, дати
- [ ] Кнопка «Провести» + показ статусу + помилки нестачі залишків
- [ ] 2D-схема складу: заповненість полиць (колір + відсоток) + легенда
- [ ] Сторінка стелажа: заповненість кожної полиці (об'єм і вага)

## 8. Тести
- [ ] CRUD довідників (постачальники/одержувачі) + валідація полів
- [ ] Ієрархія стелаж → полиця та відображення заповненості
- [ ] API вихідних накладних з перевіркою залишків
- [ ] Проведення накладнів + граничні випадки залишків
- [ ] Регресія: увесь наявний набір тестів зелений

## 9. Верифікація
- [ ] `pytest` — усі тести зелені
- [ ] `npm run build` (tsc + vite) — без помилок
- [ ] Живий прогін API (curl) і UI
- [ ] Коміт, push, PR і merge у `main`
